# Role-agnostic primitives; all policy lives with the consumer

a2a ships independent CLI primitives (watch, inbox, fetch, notify, state) and contains no notion of roles such as router or worker, and no logic deciding who should handle what. Relevance is expressed only through Filter Rules in config (combined with OR, with every Matched Rule recorded), and everything beyond that — triage, routing, escalation — is built by the consumer composing commands and using State. This keeps one tool usable by routing agents, solo agents and humans alike; the cost is that common workflows must be assembled from parts rather than switched on. Agent-specific integrations (e.g. a Claude Code plugin) are packaging around the core and must not leak into the `a2a/` package; the `command` Sink is the core's only extension point for delivery.
